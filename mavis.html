MULTIMODAL PERSONAL ASSISTANT

Mavis.

An assistant is more useful when it can work with the context you already have.

Mavis is a personal AI assistant that brings conversation, live web research, and file understanding into one workspace. The project has evolved from a local voice-driven experiment into a browser-based assistant designed to keep useful context close.

01 / THE CONTEXT

THE IDEA

Useful context lives
in too many places.

THE FRICTION

A question can depend on a document, a web page, an image, or something said earlier in a conversation. Moving between those sources makes it harder to keep the thread of the task.

THE APPROACH

Mavis brings those inputs into a single conversation. Ask directly, search the live web, attach supported files, or keep a thread for later without turning the interface into a maze of separate tools.

04 / MY ROLE

FROM DESKTOP EXPERIMENT TO WEB APP

Same curiosity.
A different surface.

The earlier local prototype explored typed and voice interaction, including Windows-specific desktop commands. The newer web direction focuses on conversational research, multimodal input, and a more controlled browser experience.

  • Personal project: product direction, implementation, and iteration.
  • Built a React and TypeScript frontend around a Python FastAPI service.
  • Integrated web search, document processing, image input, and model-provider fallback.
  • Kept owner-only and machine-level experiments separate from the public web experience.
Current scope: Mavis is being rebuilt. The old local voice/PC-control prototype is not the same as the current web assistant, and PC control is disabled in the hosted backend configuration.
05 / ENGINEERING NOTES

THE CHALLENGE

One conversation,
many kinds of context.

Mavis has to handle more than a plain text prompt: a conversation can involve uploaded files, images, a page URL, or a live web search. Each source needs to become useful context without pretending that the assistant has read something it has not.

  • Challenge: Bring different input types and external tools into one conversational workflow.
  • Decision: Keep model calls and tool execution behind the server API, with dedicated URL-reading, web-search, and document-processing paths.
  • Learning: A useful assistant depends as much on reliable context handling, clear tool boundaries, and honest source attribution as it does on the model response.

MAVIS / STILL EVOLVING

The aim is not another chat box. It is a more useful place to think.
